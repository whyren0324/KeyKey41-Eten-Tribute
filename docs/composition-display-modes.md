# 組字顯示模式設計

KeyKey 41 提供三種「文字尚未確認」時的顯示方式。三種模式只改變組字中的視覺呈現，不改變選字、Enter 確認、Esc 清除或實際送入應用程式的文字。

## 1. 實線底線

- 組字文字保留在應用程式的原輸入位置。
- 在組字文字下方顯示實線，清楚標示尚未確認的範圍。
- 使用 TSF `TF_DISPLAYATTRIBUTE` 的 `TF_LS_SOLID` 樣式，讓 Win32、UWP 與 Chromium/Electron text host 都能穩定顯示。

## 2. 微軟注音（虛線）

- 組字文字保留在應用程式的原輸入位置。
- 使用 TSF `TF_LS_DOT` 點狀底線，盡量貼近微軟注音的顯示方式。
- 文字與背景顏色由應用程式及 Windows 主題決定。

## 3. Yahoo KeyKey（浮動組字框）

- TSF 仍維持一個空的組字範圍，以保留正確的確認、取消及游標位置語意。
- 未確認文字由 server-side popup 顯示，不會預先插入文件。
- 浮動框使用比一般正文稍大的微軟正黑體、淺色背景、深色文字、細灰框及紫色右側游標；不使用誇張放大的提示字級。
- 框內最多保留 10 個可修改的已組成字元。產生第 11 個字元時，引擎會按完整詞節／詞節點從最前方自動送出足夠的文字，使框內重新維持最多 10 個字元；已送出的部分不再受 Backspace 或候選字修改影響。
- 視窗跟隨 TSF 回報的輸入位置；優先放在游標右側，空間不足時移至左側，並限制於目前螢幕工作區。
- 完成確認後，TSF 將最終文字一次寫入原本的空組字範圍。

## 相容性注意事項

- x64 與 x86 TIP 共用相同 IPC 欄位及顯示模式。
- 模式 1、2 的實際底線與文字顏色由宿主程式繪製；少數不完整支援 TSF display attributes 的舊程式可能忽略部分樣式。
- 模式 3 由 KeyKey 41 自行繪製，較不依賴宿主的組字樣式能力，但輸入位置仍取決於宿主回報的 TSF caret rectangle。
- 必須測試 Notepad、Office、Chromium/Electron、傳統 Win32/x86 軟體、多螢幕、不同 DPI，以及螢幕四周邊界。
- IPC payload 新增顯示模式及文字顏色欄位；升級後已開啟且仍載入舊 TIP DLL 的程式應重新啟動。

## 測試工具

`CompositionDisplayPreview` 是原生 Win32 視覺預覽工具。`tests/CaptureCompositionPreview.ps1` 可擷取顏色提示與 KeyKey 浮動框的測試畫面；它不會產生 MSI，也不會變更系統輸入法註冊。
